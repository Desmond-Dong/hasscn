---
title: "AI 政策"
---

我们支持在贡献 Open Home Foundation 项目时使用 AI（即 LLMs）作为工具。然而，你对你提交的所有贡献负责，我们对合并并发布的所有贡献负责。我们对我们项目的所有贡献都持高标准。

我们的维护者投入时间和精力来审查贡献。提交你自己未经审查和理解的 AI 生成内容会浪费这些时间，将不会被接受。

## 自主代理（Autonomous agents）

**我们不允许使用自主代理来为我们的项目做贡献。** 我们将关闭任何我们认为由自主代理创建的 pull request 或 issue，并可能将自动化评论标记为垃圾信息。这包括绕过所提供的 issue 或 pull request 模板的贡献。

## issue、pull request 和代码审查中的沟通

如果你使用 AI 工具来帮助你写作，我们并不介意。但是，不要让工具替你在未审查的情况下发布内容。保持回复内容最低限度，仅需传达你的意图即可。我们可能会隐藏我们认为属于未审查 AI 输出的任何评论。

如果你正在发起一个 pull request，我们期望你能用自己的话解释所提出的更改。这包括 pull request 描述以及对问题的回复。如果你使用 AI 帮助生成 pull request 摘要，你必须审查其技术准确性。

**不要使用 AI 来生成对维护者问题的回答。** 你应该理解并能够解释自己的工作。使用 AI 来改善语法或清晰度是可以的，但回复的内容必须是出自你自己的。

如果你希望在评论中引用与 AI 交互的内容，必须使用引用块（例如使用 `>`）并加以披露。必须附上你自己的评论，解释该上下文的相关性和影响。不要分享长篇片段。

## 非英语母语使用者

我们理解，作为非英语母语使用者时，AI 是有用的。使用 AI 来改善你自己所写文本的语法或清晰度是可以的。如果你使用 AI 来翻译你的评论，请确保翻译准确反映了你的意图。在 details 块中附上你的原文可以展示你贡献背后的努力，有助于维护者在需要时验证翻译，并保持对话的可读性。

## 代码和文档贡献

AI 可以成为编写代码和文档的有用工具。然而，由于我们项目的基础开源性质，我们要求有人类参与循环，理解 AI 产生的工作。

所有贡献在提交前必须经过贡献者审查和理解。你应该能够解释你在 pull request 中提交的每一个更改。看起来像未审查 AI 输出的 pull request 将在不经过审查的情况下被关闭。

## 我们对 AI 的使用

我们的一些项目使用 AI 工具来辅助代码审查、issue 分类、报告和其他项目管理任务。这些工具可能会在 pull request 或 issue 上留下评论。与任何自动化工具一样，这些评论并不总是正确的。

如果 AI 工具在你的贡献上留下评论，请将其视为任何其他审查评论一样对待。如果你认为它不正确，请说明；简要解释就足够了。维护者始终拥有最终决定权。如有疑问，请咨询维护者。

## 执行

不符合本政策的贡献将被关闭。反复违规可能会导致被禁止贡献到 OHF 项目。如果你认为你的贡献被错误关闭，欢迎你联系维护者进行讨论。

## 原理说明

为了让用户了解集成的工作原理，我们应描述集成的数据是如何更新的。
这将帮助用户对集成在其使用场景下的表现建立预期。
例如，一个每 5 分钟才轮询一次的运动传感器，其可用性低于一个主动推送更新（push）的运动传感器。

由于用户可以为轮询型集成定义自己的轮询间隔，我们应说明当前的轮询速率，并描述任何限制。
例如，如果我们要连接的设备在处理过多请求时存在已知问题，我们应在文档中加以说明。

## 示例实现

```markdown showLineNumbers
## 数据更新

我的集成默认每 5 分钟从设备获取一次数据。
较新的设备（运行 MyOS 的设备）支持推送数据。
在集成启动时，我们会尝试启用该功能；如果失败，则回退到 {% term polling %}。
```

## 例外情况

本规则没有例外。
